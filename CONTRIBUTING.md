# Совместная разработка

## Требования

Рекомендуемый путь — Docker Desktop/ Docker Engine + Docker Compose v2. Альтернатива — Node.js 22.

## Запуск разработчика

```bash
git clone https://github.com/OWNER/REPOSITORY.git
cd REPOSITORY
docker compose -f devops/compose.dev.yaml up --build
```

Сайт: `http://localhost:3000/`; админ-панель: `http://localhost:3000/admin.html`.

После первого build HTML/CSS/client-side JS обновляются через bind mount. При изменении серверного кода Node перезапускается автоматически. Если изменён Dockerfile, package.json или конфигурация окружения — пересоберите контейнер:

```bash
docker compose -f devops/compose.dev.yaml up --build
```

Для локального запуска без Docker выполните `npm install`, затем `npm run dev`.

## Ветки и Pull Request

- `main` — основная согласованная ветка.
- Новую задачу делайте в отдельной ветке, например `feature/movie-search`, `fix/admin-save` или `devops/docker-layout`.
- Не делайте прямые коммиты в `main`.
- Перед PR запустите приложение у себя и пройдите затронутый пользовательский сценарий.
- В PR опишите: что изменено, как проверить, есть ли миграции/изменения данных и скриншоты для UI.
- После review и ручной проверки изменения можно вливать в `main`.

## Минимальная ручная проверка

1. Главная открывается на `http://localhost:3000/`.
2. Перейдите на изменённую страницу и проверьте сценарий, который меняли.
3. Если изменяли админку или API: сохраните тестовое изменение и обновите страницу, чтобы проверить, что оно сохранилось в SQLite.
4. Проверьте логи на ошибки: `docker compose -f devops/compose.dev.yaml logs --tail=100 app`.
5. Если затронуты другие страницы или функции, проверьте связанные сценарии.

В проекте пока нет автоматических тестов. Не отмечайте их как пройденные, если тесты не добавлены и не запускались.
