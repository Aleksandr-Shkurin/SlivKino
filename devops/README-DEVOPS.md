# SlivKino (ветка test): локальный запуск через Docker

Эта папка добавляет Docker-запуск к Laravel-проекту из архива `SlivKino-test.zip`.
Исходники приложения находятся в корне репозитория; Docker-файлы и команды управления — здесь, в `devops/`.

## Что найдено в проекте

- Laravel Framework **12.70.2** (`composer.lock`), требование проекта — PHP `^8.2` (`composer.json`).
- PHP-приложение с Blade-шаблонами, контроллерами, моделями и маршрутами.
- Vite 7 и Tailwind CSS 4 для сборки frontend-ресурсов.
- По `.env.example` база по умолчанию — **SQLite**, не MySQL.
- Сессии, кэш и очередь настроены на database-драйвер; миграции для соответствующих таблиц включены.
- Админ-панель: `/admin/login`; создание администратора реализовано Artisan-командой `app:create-admin`.
- Docker-конфигурации в исходном ZIP не было; эта папка добавляет её.

В одном из текстовых файлов есть старое упоминание MySQL, но текущая конфигурация `.env.example` задаёт `DB_CONNECTION=sqlite`, а `config/database.php` использует SQLite по умолчанию. Для локального тестового запуска Compose использует SQLite в отдельном Docker volume.

## Требования на компьютере

- Docker Desktop (Windows/macOS) или Docker Engine + Docker Compose plugin (Linux).
- Git — только чтобы клонировать/обновлять репозиторий.
- PHP, Composer, Node.js, npm и SQLite на хост устанавливать не требуется: зависимости устанавливаются в Docker image.

Нужен интернет на первом запуске, чтобы скачать базовые образы и зависимости Composer/npm.

## Первый запуск — Windows

1. Клонируйте репозиторий и переключитесь на ветку `test`.
2. Откройте корневую папку проекта в VS Code. В корне должны быть `artisan`, `composer.json`, `composer.lock`, `.env.example` и `devops/`.
3. Запустите Docker Desktop и дождитесь статуса Engine running.
4. Дважды щёлкните `devops/start-dev.bat`.

Или выполните в PowerShell из корня проекта:

```powershell
Copy-Item .env.example .env  # только если .env ещё не существует

docker compose -f devops/compose.yaml up -d
```

Первый запуск собирает образ PHP 8.3 + расширения SQLite и собирает Vite-ресурсы на Node.js 22. Он может занять несколько минут.

## Адреса

- Сайт: http://localhost:3001/
- Вход в админ-панель: http://localhost:3001/admin/login

Порт 3001 выбран, чтобы тестовая версия могла работать рядом со старой версией, которая использует 3000. Публикация привязана к `127.0.0.1`, поэтому порт не открыт в локальную сеть.

## Создать администратора

После запуска выполните из корня проекта:

```bash
docker compose -f devops/compose.yaml exec app php artisan app:create-admin admin@slivkino.local
```

Команда интерактивно спросит имя и пароль. Пароль должен содержать минимум 10 символов. Сохраните выбранные email и пароль: команда не создаёт заранее известную учётную запись.

Затем войдите на http://localhost:3001/admin/login.

## Ежедневные команды

```bash
# Старт (если образа ещё нет, Compose соберёт его автоматически)
docker compose -f devops/compose.yaml up -d

# Логи
docker compose -f devops/compose.yaml logs -f app

# Состояние
docker compose -f devops/compose.yaml ps

# Остановка без удаления данных
docker compose -f devops/compose.yaml down

# Пересобрать образ после git pull или изменений Dockerfile / зависимостей
docker compose -f devops/compose.yaml up -d --build
```

Для Windows есть `start-dev.bat`, `stop-dev.bat`, `logs-dev.bat`, `rebuild-dev.bat`. Для macOS/Linux — соответствующие `.sh`-скрипты.

## Данные и сброс

- SQLite хранится в именованном volume `slivkino-test_sqlite_data`.
- Загруженные постеры хранятся в `slivkino-test_posters_data`.
- Обычный `docker compose down` сохраняет оба тома.
- `docker compose down -v` удаляет оба тома, включая локальную базу и загруженные постеры. Не запускайте эту команду, если нужны данные.
- Миграции выполняются при запуске. Начальный `DatabaseSeeder` выполняется только один раз на новый DB-volume: в нём используются `create()`, повторный запуск способен создать дубликаты кинотеатров и фильмов.
- Не используйте `php artisan migrate:fresh` для обычного запуска: команда удалит таблицы и данные.

## Важные замечания по исходному коду

1. В `DatabaseSeeder.php` даты тестовых сеансов заданы статически как `2026-11-01`. На дату подготовки инструкции (25 ноября 2026 года) эти сеансы уже в прошлом. Фильмы и кинотеатры при этом должны быть видны; для актуального расписания добавьте новые сеансы в админ-панели или поправьте даты сидера.
2. Комментарий в `app/Models/Session.php` и один текстовый файл упоминают MySQL, но конфигурация приложения для этого запуска — SQLite. Для одиночного локального просмотра это подходит. `lockForUpdate()` в бронировании не даёт SQLite такого же поведения блокировок строк, как MySQL/PostgreSQL; не рассматривайте этот локальный режим как проверку конкурентных бронирований для production.
3. `DatabaseSeeder` не создаёт администратора. Его нужно создать отдельно командой выше.
4. В ZIP отсутствует `package-lock.json`; поэтому frontend-зависимости устанавливаются через `npm install`, а не `npm ci`. Для полностью воспроизводимой frontend-сборки разработчику следует добавить и коммитить `package-lock.json`.
5. `README.md` в архиве — стандартная заготовка Laravel и не описывает особенности этого сайта. Для административной панели есть отдельная инструкция `ADMIN-...md` в корне.

## Обновление кода из GitHub

После переключения или обновления ветки `test` пересоберите образ, потому что исходники копируются в Docker image и не монтируются как live-папка:

```bash
git switch test
git pull origin test
docker compose -f devops/compose.yaml up -d --build
```

SQLite и загруженные постеры при такой пересборке сохраняются в volumes.
